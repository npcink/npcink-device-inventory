# 3.1.4 资产生命周期与后台质量收尾规范

## 状态

2026-08-10 接受，作为 3.1.4 及后续资产管理改动的维护规范。

## 本轮目标与结果

本轮不是增加一个孤立字段，而是把设备类型、资产生命周期、财务价值、
导入导出、硬件摘要和后台信息密度整理为一致的产品契约：

- 电脑设备使用 `category` 保存笔记本、台式电脑、苹果电脑、一体机等实用类型；
- 新采集或旧数据缺少电脑类型时默认归为“台式电脑”；
- 类型贯穿新增、编辑、批量修改、筛选、导入和资产表格导出；
- 已归档资产保留历史，但退出列表、统计、分析、采集趋势和资产表格导出；
- 报废资产保留历史采购价，二手市场价和账面净值强制为零；
- 财务界面使用“账面净值（估算）”，避免把当前账面价值误称为期末残值；
- 卡片和列表只显示更新日期，详情保留完整时分秒；
- 已知远程虚拟显示驱动不再冒充主显卡，基础显示驱动只做保守的核显提示；
- 表单采用三列布局、中文日期控件和精简帮助信息，详情摘要只保留决策所需事实；
- 最终 ZIP 通过回归、静态检查、构建、官方 Plugin Check 和隔离恢复演练。

相关正式决策见：

- [`ADR-010`](decisions/ADR-010-separate-market-and-financial-residual-values.md)：二手市场价与账面价值分离；
- [`ADR-011`](decisions/ADR-011-configurable-asset-export.md)：可配置资产表格导出；
- [`ADR-012`](decisions/ADR-012-treat-archived-assets-as-business-excluded-records.md)：归档资产退出业务计算且不建设回收站。

## 核心业务契约

### 1. 顶层资产类型与电脑设备类型分层

`asset_type` 只回答“这是电脑还是自定义资产”，保持封闭值：

```text
computer | custom
```

电脑的实际形态继续使用 `category`：

```text
笔记本 | 台式电脑 | 苹果电脑 | 一体机
```

自定义资产的同一字段仍显示为“分类”。不要为了改变界面名称新增数据库列，
也不要把每一种电脑形态扩展成新的顶层 `asset_type`。

新增字段前必须检查完整消费链：数据库、REST、表单、详情、列表、筛选、批量、
导入、导出、备份、迁移和测试。只完成单一入口不算功能完成。

### 2. 归档与报废是不同边界

归档对应 `deleted`，表示保留历史但退出日常业务：

```text
business asset = status != deleted
archived record = status == deleted
```

归档不会修改采购价、二手市场价或账面净值。完整 JSON 备份仍保留归档资产；
普通资产表格导出、分析和统计不得包含它们。当前不建设回收站、自助恢复或永久删除。

报废对应 `retired`，仍是一条可见资产记录，但不再具有当前市场或账面价值：

```text
if status == retired:
    purchase_price = unchanged
    residual_value = 0
    financial_residual_value = 0
```

该规则必须覆盖新增、单台修改、批量修改、表格导入、备份恢复和历史升级迁移。
已报废资产后续即使再次提交非零价值，也必须在服务端归零。前端显示归零只是用户体验，
不能替代服务端不变量。

### 3. 财务字段必须保持语义分离

- `purchasePrice`：历史采购成本，报废和归档均保留；
- `secondHandMarketValue`：当前可能出售的市场估价；
- `financialResidualValue`：内部兼容名称，用户界面呈现为当前“账面净值（估算）”；
- `residualValue`：只作为二手市场价的旧 REST 兼容别名。

自动账面净值使用直线折旧：

```text
期末预计残值 = 采购价 × 预计残值率
月折旧额 = (采购价 − 期末预计残值) ÷ 折旧月数
当前账面净值 = max(期末预计残值, 采购价 − 月折旧额 × 已经过完整月数)
```

自动模式使用实时估算；手动模式用于减值、政策调整和历史例外。报废状态优先级最高，
无论模式为何，当前有效账面净值都为零。完整数据模型见
[`asset-data-model.md`](asset-data-model.md)。

## 后台界面规范

### 表单与信息密度

- 桌面宽度优先使用均衡的三列网格，窄屏回落为单列；
- 会阻止用户犯错的后果说明保持可见，稳定参考信息可收进可聚焦的信息图标；
- 状态字段必须提示：选择报废会保留采购价并将二手市场价、账面净值归零；
- 日期使用本地化日期选择器并保存 `YYYY-MM-DD`，不能只导入语言包而不激活 Day.js locale；
- 卡片和列表显示日期即可，详情和审计时间线保留完整时间；
- 电脑上下文使用简短标签“类型”，跨资产类型列表使用“类型 / 分类”或“资产类型”消除歧义。

### 摘要与详情

摘要只展示当前任务最有价值的事实。采购日期、采购价、二手市场价和账面净值可以占据
摘要位置；折旧模式、折旧率和账面净值率属于解释或分析信息，不应与核心事实争夺同等
视觉权重。精简不是删除信息，而是把信息移动到正确层级。

### 中文化

浏览器原生日期控件、第三方组件 locale、按钮文案和硬件占位名称需要分别检查。
“导入语言文件”不等于运行时已经切换语言；测试必须覆盖弹窗按钮、月份、星期和清空操作。

## 硬件摘要规范

硬件观测保存原始事实，卡片摘要可以做受约束的展示归一化：

- `OrayIddDriver Device` 等 IDD/远程显示设备是虚拟显示驱动，不是物理显卡；
- 主显卡摘要先过滤已知虚拟控制器，再选择物理控制器；
- `Microsoft Basic Display Adapter` 表示驱动或识别信息不足，不能当成具体显卡型号；
- 只有 CPU 型号足以支持时才给出保守的 Intel 核显提示；带 `F` 后缀的 Intel CPU 不应推断核显；
- 不根据 CPU 猜测精确显卡型号，不让展示推断进入身份匹配或原始观测数据。

原则是“原始数据可追溯，摘要可读但不伪造精度”。新增过滤规则必须配 fixture，防止远程
驱动、显示器信息和真实显卡再次混淆。

## 全链路实现检查表

### 新增或改变资产字段

- [ ] 明确字段语义、默认值和兼容别名；
- [ ] 确认数据库与迁移是否真的需要变化；
- [ ] REST 创建、修改和格式化响应一致；
- [ ] 单台、批量和导入入口行为一致；
- [ ] 筛选、详情、卡片和列表使用同一标签口径；
- [ ] Excel/CSV 字段、顺序和预览一致；
- [ ] 完整备份与恢复保持数据契约；
- [ ] 历史记录迁移幂等且有 fixture；
- [ ] 更新数据模型、ADR、changelog 和发布记录。

### 生命周期规则

- [ ] 明确该状态是否参与业务列表和计算；
- [ ] 明确上传、导入、备份恢复和资产编号冲突行为；
- [ ] 在服务端写入边界执行不变量；
- [ ] 查询和导出同时保护重要排除规则；
- [ ] 状态改变后失效所有相关缓存；
- [ ] 审计只记录真正变化的字段，避免 `0 → 0` 噪音；
- [ ] 界面提前说明不可逆或自动调整的后果。

## 开发方法与经验

1. **先澄清名词再写代码。** “残值”可能指市场售价、期末预计残值或当前账面价值；
   不先拆开语义，任何公式和报表都会产生误导。
2. **把状态定义成集合边界。** 归档不是普通筛选值，而是业务集合之外的历史记录；
   报废不是删除，而是仍可审计但当前价值为零。
3. **关键规则由服务端裁决。** 前端禁用、隐藏或显示零值都不能阻止导入、旧客户端和
   备份恢复写入不一致数据。
4. **完整功能按消费链验收。** 批量修改遗漏设备类型说明仅检查详情页是不够的；
   字段必须沿所有读取和写入路径逐项核对。
5. **默认值必须同时照顾新旧数据。** 新数据在采集/创建时规范化，旧数据通过幂等迁移
   修正，显示层仍提供兼容兜底。
6. **摘要推断必须保守。** 过滤确定的虚拟设备可以提高准确性；证据不足时应显示“驱动
   未识别”，不能为了界面好看猜出精确型号。
7. **UI 精简以任务价值排序。** 使用三列、短标签、日期精度分层和信息图标降低拥挤，
   但后果、验证错误和关键金额不能隐藏。
8. **发布包本身才是验收对象。** 源码测试通过后仍要重新构建 ZIP，在干净 WordPress、
   PHP 和数据库环境中安装，运行固定版本 PCP，并执行真实备份恢复演练。

## 验证标准

受影响功能至少执行：

```bash
npm run check:fixtures
npm run build:release
npm run check:release
npm run check:docker
git diff --check
```

前端迭代还需执行 `npm run lint` 和 `npm run build`（目录 `vite-admin`）。发布完成的证据必须
包含最终 ZIP 路径、SHA-256、官方 PCP 的 `Checks complete. No errors found.` 和
`Isolated Docker verification passed.`。构建警告应记录，但不得把警告误报为成功或失败。

## 明确不做的事情

- 不新增回收站页面、自助恢复或永久删除；
- 不为电脑形态扩展顶层资产类型；
- 不把报废简化成物理删除；
- 不清除报废资产的采购历史；
- 不把二手市场价自动复制为账面净值；
- 不依赖前端维持财务不变量；
- 不根据 CPU 或虚拟显示驱动伪造精确显卡型号。

只有出现重复、可量化的真实业务需求时，才重新评估这些边界，并通过新的 ADR 记录权限、
迁移、冲突、审计和恢复方案。
