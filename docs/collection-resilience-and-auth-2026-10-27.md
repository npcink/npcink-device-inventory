# 采集异常恢复与上传授权收尾

## 合同

采集查询以逐条 NDJSON 记录输出。只有完整且有效的记录才进入硬件事实；成功后发生错误、超时或输出截断时，保留已完成记录并标为 partial。单盘健康读取失败保存来源标识和错误，不将错误信息充当健康指标；其他盘继续读取。partial 与 failed 沿用60秒短缓存。

Windows 可选阶段总预算仍为12秒：先以最多8秒并发执行显示、电池、机箱、安全及外设两组，随后把剩余时间交给独立存储关系/健康进程。正常执行增加一次 PowerShell 启动，最大并发仍为2；存储不能阻止前面的安全及外设查询执行。前两组提前结束时，剩余时间全部归存储。受共享60秒外部预算约束，预算不足时同比缩短。

## HMAC 请求签名 v2

保持 observation schema5、身份算法及现有授权码格式；只接受签名版本2，旧签名无回退。请求携带 `x-npcink-device-signature-version: 2`；HMAC-SHA256 的UTF-8原文按以下行序拼接，末尾不附加换行：

```text
npcink-device-upload-v2
<大写 HTTP 方法>
<规范化 WordPress REST 路由>
<Token ID>
<秒级 Unix 时间戳>
<nonce>
<原始请求体 SHA-256 小写十六进制>
```

允许范围固定为：

- `POST /npcink-device-inventory/v1/device-observations`
- `GET /npcink-device-inventory/v1/device-observations/verify`

路径指 WordPress `get_route()` 的逻辑 REST 路由，去除末尾斜杠；不含站点子目录、REST前缀或域名。客户端从 pretty URL 或唯一 `rest_route` 参数解析同一路由。只允许路由参数，不接受未签名的其他 query 参数。时间窗、nonce原子防重放及按token限流继续有效；错误签名不能消耗合法nonce。修改方法、路由、Token ID或请求体必须使原签名失效。

旧客户端连接将收到明确的签名版本错误，需与插件配套更新；不因此重生成或吊销现有授权码。部署依然先插件后客户端，本阶段不部署安装包或远端站点。

## Token 范围复核

当前授权码是站点级、多设备采集凭据，仅可提交观测和验证连接，不能用于读取台账、备份、修改资产或管理设置。设备归属继续由服务端v2身份计算、冲突检查和事务裁决。

持有该凭据的人可以提交其他设备的硬件事实；HMAC证明持有密钥，不证明硬件事实真实。当前产品允许多设备首次登记，本阶段不增加首次绑定或按编号限制；自动把共享token绑定到第一台上传设备会阻断现有流程。若以后要引入逐设备授权，应单独定义管理员登记、设备替换、撤销与恢复合同。
