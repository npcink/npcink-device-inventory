# M4 Docker 上传链路验收（2026-11-17）

## 环境与范围

在可通过 SSH 访问的 Apple M4、macOS 26.6.2 上，自动搭建独立 Compose 项目 `npcink-agent047-acceptance`。Docker Server 为 29.9.2，WordPress 7.1.4、PHP 8.3.36、插件 3.2.4；MariaDB 与 WordPress 复用已有镜像，使用新命名卷。HTTPS 故障网关仅发布 `127.0.0.1:18447`，没有改动其他 Compose 项目、系统代理或系统证书信任。

客户端侧在 M4 原生执行 arm64 Rust 验收探针，由 M5 编译后复制到 M4。探针复用 0.4.7 的采集模块，并逐字节包含未修改的 `ele-rs/src/upload.rs`。探针锁文件与共享库锁文件相比只增加验收程序的本地 package，没有更新网络依赖版本。生产源来自 `3b55a64`；后续分支提交仅为文档。

本次执行真实 M4 采集、HTTPS、HMAC v2、真实插件及 MariaDB 写入。硬件只在内存及本次隔离数据库中使用，不输出原始硬件。每个独立上传用例使用新观测编号；同一次自动重试保留相同编号和字节。

## TLS 与代理边界

发布配置使用内置公共根证书。本地临时 CA 不在其中：未改动的生产连接验证在约 10ms 内返回 `tls`，只尝试一次，没有关闭证书或主机名验证。

后续成功链路使用仅在独立探针中加入的本次临时 CA，仍执行证书链和主机名验证。探针显式直连回环地址，以便隔离故障注入；未修改发布包的信任范围，也未将 CA 安装到系统。因此这些结果证明上传核心到真实后端的行为，不证明原样 DMG 已完成可信 HTTPS GUI 上传。

M4 的手动 HTTP、HTTPS、SOCKS 系统代理处于启用状态；本次只记录启用标志，没有读取或记录认证信息。成功链路明确绕过代理，不能把它计作系统代理路径验收。PAC、系统代理实际转发、跨网络公网 HTTPS 和原故障根因仍未确认。

## 实测结果

首轮 19 个用例全部通过，另补一轮显式 TCP reset；每轮均包含默认 TLS 拒绝检查。HTTP 状态故障由隔离网关注入，401 签名失败由真实 WordPress 验证产生。下表时间为上传核心累计网络与退避耗时，不含采集、取证和容器 CLI 开销。

| 用例 | 尝试次数 / 耗时 | 结果 |
| --- | --- | --- |
| 默认客户端拒绝临时 CA | 1 / 10ms | `tls`，不重试 |
| 探针信任指定 CA 后验证连接 | 1 / 202ms | 真实插件连接验证成功 |
| 真实 M4 数据上传 | 1 / 38ms | 成功，新增一条观测 |
| 后端入库后，网关将首次成功响应替换为 503 | 2 / 517ms | 重试成功；两次后端返回同一 receipt，仅新增一条观测 |
| 首次响应丢失、读超时后恢复 | 2 / 15583ms | 首次分类 `timeout`，第二次成功，新增一条观测 |
| 显式 TCP reset 后恢复（补测） | 2 / 607ms | 首次 7ms 分类 `connection_reset`，第二次成功，新增一条观测 |
| 错误签名 | 1 / 20ms | 真实插件返回 401，不重试 |
| 302 | 1 / 4ms | `redirect`，未访问跳转目标 |
| 403 / 404 / 409 / 413 | 各 1 / 5–8ms | 明确 HTTP 错误，不重试 |
| 429，Retry-After 为 1 秒 | 1 / 4ms | 不自动重试，提示等待建议 |
| 持续 502 / 503 / 504 | 各 3 / 1387、2034、1392ms | 有限重试后明确失败；503 尊重 1 秒 Retry-After |
| 503 携带已知 invalid_signature 业务码 | 1 / 3ms | 业务错误否决重试 |
| 200 HTML | 1 / 10ms | `non_json`，不回显远端正文 |
| 200 超过 64 KiB 响应 | 1 / 4ms | `response_limit_or_encoding`，不重试 |
| 持续响应超时 | 3 / 45003ms | `timeout`，符合 45 秒预算及调度误差范围 |

首轮名为 `reset_then_success` 的夹具实际触发了读超时，不能作为 TCP reset 证据。复核发现后补充 SO_LINGER TCP reset 注入，第二轮进度事件明确记录 `connection_reset`，两组证据分开保存。

网关只保留比较结果和计数，不持久化请求体、timestamp、nonce 或完整签名。交叉核对请求数与客户端尝试数一致；重试请求体相同，timestamp、nonce、签名各次不同。HMAC 与探针配置一致，正常转发请求通过真实插件验签；错误签名用例故意让探针密钥与插件不同，插件按预期拒绝。302 目标命中数为零。

所有错误用例没有新增观测。首轮成功操作共新增三条，补测 TCP reset 新增一条；清理前数据库合计一条资产、四条观测。远端 HTML/token 哨兵以及真实临时授权码均未出现在客户端错误和进度记录中。
