# 上传可靠性开发与收尾规范

本文将 2026-11-17 至 18 日上传错误处理、M4 验收与会话收尾经验固定为后续工作规则。错误表和参数以[网络策略](upload-network-resilience-2026-11-17.md)为准，现场操作以[运维手册](device-upload-troubleshooting-and-operations.md)为准，版本与发布按[正式候选流程](github-release.md)执行。

## 先分清事实、推断和处理结果

- “失败后稍后成功”只能支持暂时故障假设，不能证明服务器、DNS、代理或证书是根因。缺少当时日志时保留未知结论。
- UI 丢失底层错误分类是已查明并修复的实现问题；历史 M4 网络故障的具体根因仍未查明。这是两个不同结论。
- 故障报告至少包含类别、HTTP 状态、尝试次数、累计网络耗时、客户端版本和脱敏站点标识。收集这些事实后再决定改网络、配置或代码。
- 安全边界不因排障放宽：仅 HTTPS、不跟随重定向、限制请求与响应、校验 payload 与响应合同、仅显示已知业务码；不展示远端 HTML、任意 message 或堆栈。

## 重试必须同时满足传输与业务合同

- 只重试已确认暂时性的失败；未知连接错误保守停止，不能以“也许会好”为由重发所有错误。
- 自动重试的基础是同一 observation_id 和完全相同的请求体对应同一 receipt；每次重新生成 timestamp、nonce 与 HMAC。不能重新采集或重建带当前时间的请求体来冒充重试。
- 应用层统一管理次数、退避与总预算，并禁用网络库的隐藏重试。Retry-After 不得绕过总预算；认证、身份、数据及其他已知业务失败否决重试。
- 总网络预算不包含硬件采集、本地编码和日志 I/O。报告耗时时写明范围，不能据网络预算承诺整个 GUI 操作一定在相同时间内结束。
- UI 使用每次调用独立的进度来源和过期消息隔离；成功时清理过程提示。阻塞 HTTP 与退避留在后台线程，原生退出行为另外实测。

## 依赖与网络环境依据配置确认

- 核对 Cargo features、锁文件和实际平台实现；不能从“reqwest 支持代理”推断当前禁用默认 features 的构建会读取 macOS 系统设置。
- 区分手动系统 HTTP(S)、环境代理、NO_PROXY、SOCKS、PAC 和系统例外列表。只声明已证实支持和已实际验证的路径。
- 为某次 Git 命令使用现有代理的结果不能解释另一次客户端上传。开发机 M5 的结果也不能自动计入 M4 验收。
- 测试不改共享代理或系统信任。若需新增外部转发路径，先明确站点暴露和数据流向；本轮用户选择暂不建立 Cloudflare 隧道。

## 夹具必须证明其声称的故障

- 通过客户端实际分类、服务端计数和耗时共同确认注入结果；夹具叫 reset，不代表真的产生了 TCP reset。
- 本轮首次关闭连接实际引起 15 秒读超时。发现后保留原证据并按超时恢复记录，另用显式 TCP reset 补测，事件确认 connection_reset 后才记录该项通过。
- 重要重试场景应模拟“后端已入库，成功响应丢失”，比较两次 receipt 和观测增量；只在发送前返回 503 不足以证明幂等。
- 只记录签名与请求体是否相同/不同以及计数，不持久化认证头、完整签名或原始硬件来取证。

## 验收结论必须标出层级

| 证据 | 能证明 | 仍需另外验证 |
| --- | --- | --- |
| Rust fixture | 分类、预算、签名刷新、边界和重试规则 | 实机网络与原生窗口 |
| 浏览器 + 合成 IPC | 前端交互、过期消息和提示清理 | 原生 Tauri 后端、系统凭据和退出 |
| M4 原生探针 + Docker WordPress | 真实采集、签名、后端写入与重试幂等 | 原样安装包、可信 HTTPS、实际系统代理 |
| 探针单独信任临时 CA | 在指定信任范围内仍校验证书和主机名 | 发布包的公共根证书路径 |
| 原 CI App 安装、启动采集、空闲 quit AppleEvent | 原生可启动、IPC 采集、正常空闲退出 | GUI 渲染、菜单/窗口交互、重试期间退出 |
| 完整 ad-hoc 资源签名 | 包完整性 | Developer ID、公证、Gatekeeper 信任 |
| Windows CI 源码 smoke | runner 上采集与构建 | 普通用户、安装/升级、凭据保留和真实上传 |

每份记录固定源提交、版本、主机、制品 SHA256 和检查范围。签名、公证或重新构建改变字节后必须重新验收，不能继承旧哈希对应的结论。锁屏或 UI 查询超时记录为受限，不能擅自写成权限拒绝或 GUI 测试通过。

## 收尾与交接的必要结果

1. 分别核对工作区干净、commit、push、开发分支集成、master 集成和发布，不能互相替代。
2. 当前入口链接到最新验收与待办，旧记录保留原范围并标明后续记录；经验进入本规范，执行记录留在日期文档。
3. 关闭会话前把未完成项写清前置环境、通过条件和后续入口。正常结束会话不会自动执行待办，也不能暗示后台仍在监控。
4. 删除临时容器、专用卷和密钥；安装后供后续实测的 App 属于保留交付物，应记录位置和运行状态。
5. 归档 worktree 前，先将被 Git 忽略的安装包、截图、探针和日志复制到长期保留的主工作区，逐文件核对哈希。Git 提交或 worktree 快照不能代替被忽略文件的备份。
6. 仅清理本轮已集成且远端保存的临时分支。其他历史分支有分叉、独有提交或未确认用途时保留；不使用批量强删或 force push 来制造“全部干净”。
7. master 上的大范围历史积压需要独立审查和全范围质量门。本轮小任务的通过不能作为整条长期开发分支直接合入主线的依据。
