# 管理端只读分析开发规范

## 目的

本规范用于新增或修改 WordPress 管理端的分析、汇总、筛选、下钻和设备只读详情。它补充 [`development-playbook.md`](development-playbook.md)；架构边界以 [`ADR-009`](decisions/ADR-009-restore-read-only-analysis.md) 为准。

## 1. 产品边界

分析功能默认只回答“当前事实是什么”和“哪些记录符合明确规则”。未经新 ADR，不得在分析层新增：

- 已处理、待办、工单、审批或采购任务状态。
- 自动修改部门、责任人、金额、状态或身份。
- 匿名访问、访问码或非管理员接口。
- 任意字段、任意 JSON 路径或任意正则查询。
- 新的数据表、定时快照或通用报表引擎。

如果需求需要写入，先明确写入对象、权限、审计事件、失败行为和撤销方式，不得把按钮偷偷加进只读组件。

## 2. 数据口径

### 缺失值

- 缺失金额显示“未登记”，不得按零参与总额、折价或残值率。
- 缺少计算所需任一字段时显示“无法计算”，不得猜测。
- 缺少某次硬件字段不能解释为硬件拆除。
- 空部门、`未分配` 和历史 `默认` 可在分析中归为待分配，但不得自动改写资产。

### 时间

- 说明使用的是采集时间、接收时间、创建时间还是更新时间。
- 日聚合按 WordPress 站点时区计算。
- 趋势必须补齐没有数据的日期，避免折线或柱状图产生连续性错觉。
- 购置日期只使用明确保存的购置信息，不用资产创建时间替代。

### 容量

- 内存和磁盘比较统一使用字节换算，展示时再转换单位。
- 标称磁盘阈值允许约 8% 的系统显示容量差异。
- 未采集容量不自动判为低配置。

### 文本型号

- 展示保留原始型号。
- 查询规范化只能移除明确列出的厂商词、商标和多余空格。
- 不同字段之间 AND；同字段多值 OR。
- 同时提供宽松系列匹配和规范化后的精确匹配，并在界面解释差异。

## 3. 查询架构

- 固定、小范围、数据库更适合完成的聚合放在服务端，例如最近 30 天观测计数。
- 当前资产列表已经加载且规模可控的组合筛选可在浏览器端完成。
- 浏览器端实现必须记录重新评估条件；当前约在 1000 台或出现可测交互下降时评估服务端查询。
- 服务端接口使用白名单参数、固定字段和管理员权限，不接受原始 SQL、正则或 JSON 路径。
- 历史数据只在用户进入需要的视图时加载，并保持分页；禁止所有分析标签同时预取全部历史。
- 聚合查询必须限定范围并复用缓存失效机制，避免新增独立缓存真相。

## 4. 只读详情与权限

- 资产详情事实使用共享组件，不为分析页复制第二套详情。
- 调用方通过显式 `readOnly` 或等价能力控制写入入口。
- 只读模式隐藏手动记录、设置、归档和所有保存按钮。
- 弹窗关闭后保留筛选、分页、标签和滚动上下文。
- 连续查看使用当前结果集，不重新查询一个口径不同的列表。
- 分析详情首屏应包含识别信息、采集时间、核心硬件和明确登记的财务事实。

## 5. 管理端界面规范

### 信息层级

首屏顺序建议为：

1. 当前查询或结果集位置。
2. 设备识别信息与采集时间。
3. 采购价、残值等关键资产事实。
4. 核心硬件。
5. 历史、调试和低频信息。

不要为简短说明单独创建与主要结果同等权重的大卡片。帮助文字优先使用字段提示或紧凑说明。

### 密度和尺寸

- 普通只读电脑详情桌面宽度约 780px；需要编辑表单时可约 840px。
- 弹窗上下至少保留约 32px，正文内部滚动。
- 硬件型号允许换行，但卡片不得依赖固定单行高度。
- 统一使用项目既有的 8–10px 圆角规则，不混用过多圆角尺度。
- 一个页面只保留一个主强调色；状态色只用于具有真实语义的状态。

### 响应式

- 所有多列网格必须显式定义 782px 以下布局。
- 父级 CSS Grid 使用 `minmax(0, 1fr)`，子项使用 `min-width: 0`，防止表格和长型号撑宽页面。
- 390px 验收时 `document.body.scrollWidth` 不得大于视口宽度。
- 表格可以在自身容器横向滚动，但不能让整个 WordPress 页面横向滚动。

### 交互

- 条件标签应支持单独删除；无条件时不要保留空占位区。
- 重置按钮只在存在条件时显示或启用。
- 点击结果详情不得破坏当前查询上下文。
- 重要动作必须使用明确文字；图标只作为辅助，不能成为唯一含义。
- 加载、空结果和错误状态必须分别表达，不能都显示成空表格。

## 6. 性能和可维护性

- 大型 `useMemo` 只用于确实有成本且依赖明确的计算。
- 避免在表格每个单元格中重复构造同一个完整结果数组；需要时先生成稳定的候选资产数组。
- 共享详情组件的只读模式不得初始化不必要的写入请求或自动提交副作用。
- 新增设置必须同时覆盖默认值、读取、保存、类型、完整备份导出和恢复。
- 新增 REST 返回值必须在前端定义类型，并保持服务端和客户端字段名称一致。

## 7. 安全规范

- 所有分析 REST 路由必须使用管理员权限回调。
- 数据库查询使用 `$wpdb->prepare()`；动态表名仅使用插件内部解析的表名和 `%i`。
- 输入在边界校验，输出由 React 或 WordPress 正确转义。
- 分析页不能因为“只读”而绕过权限检查。
- CSV 只导出当前管理员有权查看的事实，不包含令牌、签名、原始凭据或无必要的原始上传数据。

## 8. 验证矩阵

每次分析改动至少验证：

| 范围 | 验证 |
| --- | --- |
| 前端逻辑 | ESLint、TypeScript、Vite build、相关固定夹具 |
| PHP 接口或设置 | PHP fixtures、PHPCS、PHPStan |
| 查询语义 | 无条件、单条件、跨字段 AND、同字段 OR、空结果、缺失值 |
| 详情 | 当前页打开、关闭后状态保留、只读入口隐藏、上一台/下一台 |
| 响应式 | 常规桌面、1280×720 低高度、390px 移动端 |
| 运行状态 | 控制台无 warning/error，页面无整体横向溢出 |
| 备份 | 新设置可导出、预览并恢复，边界值被服务端限制 |

真实数据验收必须记录至少一个可复核结果，例如筛选词、命中数量、部门和具体资产编号。不能只写“页面正常”。

## 9. 变更完成条件

分析功能只有同时满足以下条件才算完成：

- 数据口径和排除项已写入 ADR 或规范。
- 代码中没有分析写入入口或隐式状态扩张。
- 新设置和接口具有契约与备份闭环。
- 自动检查与真实后台验收均通过。
- 文档入口已更新，未来维护者能找到当前规则。
