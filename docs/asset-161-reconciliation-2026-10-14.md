# 161 号资产重装后的重复记录修复

事件日期：2026-10-13 至 2026-10-14。2026-10-30 根据会话「a02」完整历史及本地修复证据补录。

## 问题与根因

161 号电脑重装系统后上传，服务端新建了 `E2E261013090458905`，没有关联到原资产。用户确认两条记录属于同一台物理电脑。

原资产没有可供匹配的有效身份：系统 UUID 是已知共享占位值，主板序列号是 OEM 默认串，历史数据只有当前 MAC，没有永久 PCI MAC。新上传取得了有效 v2 身份，但旧资产没有相应身份拥有者记录，因此进入首次创建分支。

资产编号、型号、使用人和重装前后的主机名不能证明物理设备相同。`inactive`（闲置）状态也不是本次原因。身份契约见 [identity-contract.md](identity-contract.md)；当前运行时只使用 v2 身份，历史兼容层已按 [ADR-017](decisions/ADR-017-remove-historical-compatibility.md) 退出，不能把本次人工修复改成按编号自动合并。

## 可复用处理规范

1. 先确认目标环境、完整备份和两条记录的固定 ID/UUID，再用真实硬件事实核对是否同一台设备。显示编号只用于查找候选。
2. 预检身份拥有者、全部观测、事件和最新指针；只允许符合预期数量与归属的固定目标进入修复。
3. 在同一事务内迁移身份、观测和事件，保留原资产业务字段，重算 latest，清理重复记录指针并归档；任一步骤失败整体回滚。
4. 给两条资产写入审计说明，修复后重新备份并逐项核验。仅改名或仅转移一条身份不能替代完整关系修复。
5. 后续由原设备重新上传时核对 receipt 中的资产标识与观测数量。没有这份证据时，将结论限定为数据修复及离线匹配核验完成。
