## 完整度与效率的具体取舍

- 身份、内存条、物理盘、GPU、主板/整机/OS 在核心阶段；外设、存储可靠性和安全状态后置。正常 Windows 采集使用四个批进程，必要时增加最多三次网卡降级进程；最多两个同时运行。CIM 单查询设置 4 秒 provider timeout，外部进程的阶段超时负责限制实际等待。某个核心查询挂起仍可能阻止同组后续项，因此诊断明确区分 query_timeout 与 budget_exhausted，不声称每台机器必然采全。
- 外部查询共享 60 秒预算；macOS 单命令最多 12 秒。进程终止后只提供有界的管道排空宽限，保留已收到内容；不使用无法取消的后台查询冒充完成。
- 取消 Windows 单独 UUID 查询，复用 system_product。sysinfo 从 new_all + refresh_all 改为只刷新需要的 CPU 和内存，不枚举全进程。
- 不静默裁剪大数据伪装完整。超限时给出原因，用户可导出本地硬件反馈；当前没有引入大型诊断附件协议或扩大服务端包体上限。
- Windows 内存速度按 SMBIOS 数据率标注 MT/s，保留配置和标称值；Mac 保留 dimm_speed 原始单位和文本。历史观测缺少单位时显示“单位未记录”，不自动换算或猜测。未知值与真实 0/false 仍区分。
- 没有新增采集运行时或第三方依赖，没有为普通库存引入 Node/Perl/C# 服务、驱动或提权流程。

## 本地测量

本机 macOS、debug 构建、未上传：一次完整采集 900 ms，紧凑库存 JSON 20,872 字节（约20.4 KiB），23条诊断记录，17成功、6无记录、0失败。该样本包含组级和子类型诊断，数量不是物理设备数。系统未报告的空类别不算丢失记录。结果受系统缓存、外设和负载影响，没有完整采集前后同条件基线，不能据此宣称整体提速比例。

单独比较 sysinfo 初始化路径，交替运行5轮，中位数：原 new_all + refresh_all 为6,924 μs，定向 CPU/内存为440 μs；两路径逻辑 CPU 数与总内存一致。此收益仅代表基础刷新部分，完整采集时间仍主要受平台探针影响。

原始本机快照只保存在临时文件，没有写入仓库或上传站点。测试日志位于临时目录。
