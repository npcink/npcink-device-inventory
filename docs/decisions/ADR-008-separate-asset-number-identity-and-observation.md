# ADR-008：严格分离资产编号、设备身份与硬件观测

## 状态

已接受，2026-08-05。

本决策补充 ADR-004 和 ADR-006：不改变硬件身份 v2 算法，而是固定管理编号、身份声明和可更换硬件数据之间的责任边界。

## 背景

项目在旧新上传器并行、历史编号调整和硬件采集补齐过程中出现过三类容易混淆的问题：

1. 同一台电脑由旧上传器建立为编号 153，新 Agent 又以自动生成编号 `E2E260805073327495` 上传。两条记录的展示编号不同，但物理设备相同。
2. 删除或归档旧 153 后，直接把新记录改成 153，数据库唯一约束失败，旧接口只返回通用 `asset_update_failed / 500`，无法说明真实原因。
3. 显示器、物理硬盘、网关、电池等信息缺失时，容易产生“是否要把更多硬件加入唯一定位”的冲动；这会使正常更换配件导致设备身份漂移。

这些问题的共同根因不是某个字段采集不足，而是三个概念被放在同一个“设备编号/指纹”想象中：行政编号、物理设备身份和某次采集到的硬件组成。

## 决策

### 1. 资产编号是受唯一约束的管理标识

- `asset_number` 用于人员沟通、标签、搜索和业务管理，不参与自动硬件匹配。
- 编号在活动资产和已归档资产之间全局唯一；归档不会释放编号。
- 复用编号必须先把原资产改为另一个明确编号，再按需要归档；不能依赖删除、归档或新上传隐式转移编号。
- 编号冲突在业务预检查阶段返回 `409 duplicate_number`；数据库重复键作为并发兜底也必须映射成相同 409，不得返回通用 500。

### 2. 设备身份只由服务端从稳定事实计算

- 当前身份类型以 `system_uuid_v2`、`baseboard_serial_v2` 和受约束的 `pci_permanent_mac_v2` 为准。
- 客户端编号、上传备注、主机名、使用人和设备型号不能改变身份拥有者。
- 同一物理设备因旧新上传器形成两条资产时，应先核对身份与观测，再执行显式重编号、合并或数据修复；不能仅根据编号相似或操作人员判断自动合并。
- 身份证据指向不同资产时失败关闭，不猜测、不覆盖。

### 3. 可更换硬件只属于观测

显示器、显卡、内存、硬盘、网卡、电池、IP、网关和 DNS 都记录在 observation 中，用于盘点、变更核对和排障，不参与唯一设备身份。

- 物理硬盘与文件系统/挂载点分层保存，避免把卷当作硬盘资产重复统计。
- 采集源不支持、权限不足、EDID 被 KVM/扩展坞隐藏时允许字段为空，不能阻断其他事实上传。
- 多来源无法可靠对应时宁可留空，不用控制器级数据伪造逐设备数据。

### 4. Agent 与 WordPress 分别承担不同责任

- Agent 负责尽可能准确地采集和上传硬件事实，并提供本地反馈/诊断证据。
- WordPress 负责身份计算、编号唯一性、事务写入、明确错误码、观测留存和后台展示。
- 正式环境不建设常驻完整在线调试平台；继续遵循 ADR-007 的轻量诊断闭环。

## 替代方案

### 归档即释放资产编号

操作简单，但归档记录仍会参与恢复、审计和历史查询；允许新旧资产共享编号会使备份恢复与人工核对产生歧义，因此拒绝。

### 把硬盘、显示器或当前 MAC 加入设备指纹

短期可增加字段数量，却会让配件更换、扩展坞、KVM 或网络切换产生新设备，违背资产管理的连续性，因此拒绝。

### Agent 直接决定资产 UUID 和编号

可减少服务端逻辑，但客户端可被替换、升级或伪造，也无法原子检查全站唯一性，因此拒绝。

## 后果

- 管理员处理旧新上传器重复记录时必须先核对身份和观测，操作步骤更显式，但不会静默污染历史。
- 后端错误语义更稳定，前端可对编号冲突给出可行动提示。
- 采集能力可以持续扩展而不改变身份契约；新增字段默认进入观测层。
- 任何未来“归档释放编号”“自动合并设备”或“新部件参与身份”的需求都必须另立 ADR，并定义迁移与回滚。
