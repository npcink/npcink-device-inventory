# ADR-009：恢复只读的数据分析视图

## 状态

已接受，2026-08-05。

本决策仅取代 ADR-003 中“分析中心不提供趋势或价值分析”的部分。ADR-003 关于删除可写问题状态、批量整改、公开查询和高级身份治理的决定继续有效。

## 背景

ADR-003 在首次真实使用前主动删除了未经验证的高级分析能力，以缩小产品范围。后续实际管理过程中，简化后的分析页只能展示四项数字和问题清单，无法回答几个常见且只需要现有事实的问题：近期是否持续收到采集、设备主要分布在哪些部门和系统、已登记资产金额的覆盖情况如何。

这些需求不要求新的业务状态、角色、定时任务或资产写入流程。资产、最新采集快照和历史观测已经是现有数据模型中的稳定事实，因此可以在不恢复旧整改工作台的前提下提供只读汇总。

## 决策

分析中心恢复并扩展以下只读视图：

1. **管理摘要**：现有概览指标、近 30 天采集次数、部门分布和资产状态分布。
2. **组合查询**：按部门、状态、使用人、显卡、CPU、最低内存和最低硬盘筛选电脑，并展示命中人员、设备和部门分布。
3. **采集健康**：按 7 天、30 天、60 天、90 天以上和从未采集分层，展示部门覆盖率和待关注设备。
4. **数据完整度**：按基础资料、最新采集、CPU、内存、硬盘、采购价和残值计算覆盖情况，并下钻到缺失项。
5. **更新候选**：根据可配置的使用年限、最低内存、最低硬盘和低残值率阈值列出候选依据；维护状态也作为一项事实依据。
6. **硬件变化**：比较每台电脑最近两次观测中双方都有值的操作系统、CPU、内存、硬盘、主板/机型和显卡字段。
7. **资产价值**：采购价、已登记残值、已知折价、金额覆盖率和部门残值分布。

组合查询在不同字段之间使用 AND，在同一字段的多个部门、状态、显卡或 CPU 值之间使用 OR。显卡和 CPU 同时提供“系列包含”与“精确型号”：系列包含会规范化大小写、空格、商标符号，并忽略 NVIDIA、GeForce、Intel、Core 等常见厂商词；精确型号则在相同规范化后要求完整相等。该规则既能用 `4060` 找到 RTX 4060 系列，也允许管理员区分桌面版和 Laptop GPU 等具体型号。

组合查询直接基于管理员页面已经加载的电脑及最新硬件事实在浏览器端建立轻量索引，不新增通用查询接口或数据表。当前资产规模适合这一实现；当电脑规模接近约 1000 台、初次加载或交互性能明显下降时，再评估带白名单字段、结构化参数和权限检查的服务端查询。不会向原始硬件 JSON 开放任意正则或任意字段查询。

新增管理员只读接口 `GET /npcink-device-inventory/v1/analysis/collection-trends`。接口固定返回最近 30 个自然日的采集快照数量，并补齐没有采集的日期。聚合查询限定日期范围、使用插件自有观测表，并沿用仓储缓存版本失效机制。

价值页只汇总资产中明确保存的金额。缺少残值时不在分析层推算当前价值；“已知折价”只计算同时具有采购价和残值的资产，避免把缺失值误当作零。

更新候选规则保存在现有插件设置中，默认值为使用年限 5 年、最低内存 8 GB、最低硬盘 256 GB、低残值率 20%。设置随完整备份导出和恢复，不新增数据表。没有采集到容量或没有购置日期、采购价、残值时，对应规则不作负面推断。

完整度是资料覆盖指标，不是资产质量评分。处于在用状态的电脑需要责任人，其他状态不因责任人为空扣分；`未分配` 不计作具体部门。所有缺失项必须能够下钻到具体资产，避免只展示无法行动的总体百分比。

真实数据验收确认旧数据还使用 `默认` 作为兜底部门，因此只读分析同时把空值、`默认` 和 `未分配` 视为待分配，不自动改写历史资产。部门采集覆盖率使用最近 30 天内有采集的电脑，而不是“历史上曾经采集过”，避免长期离线设备仍显示 100% 覆盖。

磁盘阈值比较保留 8% 的系统显示容量容差。标称 256 GB 的硬盘通常显示约 238 GB，不应因此成为更新候选；明显低于该标称档位的容量仍进入候选。

分析分布、采集分层和缺失字段支持下钻到资产列表。分析组件本身不提供写入接口，每个分析视图可以导出当前事实为 CSV。

分析结果中的资产详情改为在当前分析页内打开共享详情弹窗，不再切换到电脑或自定义资产工作区。弹窗保留硬件信息、详细信息、自动记录和调试等只读标签，隐藏手动记录、设置及其他写入入口；关闭后保留原筛选条件、分页和页面位置。组合查询结果还支持在弹窗内查看上一台或下一台命中设备。

只读详情弹窗采用紧凑的 780px 桌面宽度，并限制在当前视口内滚动；资产管理中的可写详情继续使用 840px。首屏直接展示购置日期、采购价、当前残值、已知折价和残值率。金额或购置日期没有明确登记时显示“未登记”或“无法计算”，不把缺失值解释为零，也不使用资产创建时间冒充购置日期。

硬件变化采用字段级有效比较：只有最近两次观测中同一字段都存在且内容不同才展示。某次采集缺少字段不能解释为硬件拆除。当前实现复用管理员只读的分页观测接口，不增加历史状态表。

更新计划草案由管理员在候选列表中临时勾选形成，按部门汇总已选设备的历史采购价、现有残值和两者差额，并支持 CSV 导出。选择状态只存在于当前浏览器页面会话，不持久化为采购任务或资产事件。

## 明确不恢复的能力

- 问题的“已处理 / 重新打开”持久状态。
- 从分析页批量分配部门、责任人或批量修改金额。
- 身份审计、自动身份梳理、冲突合并。
- 新的数据表、定时快照或通用报表引擎。
- 对原始硬件 JSON 执行任意正则或任意字段查询。
- 匿名或非管理员可访问的分析接口。

## 后果

- 管理员可以使用现有数据完成趋势、分布和金额覆盖检查。
- 分析页继续是只读界面，资产事实仍在资产详情、批量编辑和导入流程中维护。
- 采集趋势增加一个低成本的数据库聚合查询；查询固定为 30 天并缓存，不随资产总量把全部观测发送到浏览器。
- 若未来需要折旧预测、历史价值曲线或可写整改闭环，应单独定义数据口径、权限和验收标准，不能在当前只读接口上隐式扩张。
- 更新候选是预算与人工复核入口，不是自动淘汰结论；阈值变化只影响展示结果，不写入资产事件或状态。
- 历史采购价减现有残值只能作为参考净额，不代表未来替换设备的真实采购预算。

## 验证

- 管理端 TypeScript 构建和 ESLint 通过。
- PHP 语法、PHPCS 和 PHPStan 通过。
- 硬件审计固定夹具通过。
- 分析页不调用资产写入、事件写入或问题状态接口。
