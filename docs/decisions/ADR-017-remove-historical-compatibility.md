# ADR-017：删除历史兼容层，采用当前契约

## 状态与日期

已接受，2026-10-27。本决策替代 ADR-004 的 v1 过渡部分、ADR-006，以及 ADR-010 的旧字段兼容部分；其余当前业务边界继续有效。

## 背景

用户确认本项目目前只有本人使用，允许移除历史兼容以降低维护成本、提高性能和安全。本地预览站点 device.local 接入前没有插件业务表或资产，无须为该站点保留存量数据升级路径。

旧身份查询、迁移链、字段别名和多种备份形态增加了输入组合与测试负担。认证中为孤立测试环境保留的非原子后备实现不应进入生产运行时；上传也不应每次查询数据库列是否已经完成旧迁移。

## 决策

- 数据库直接使用 `20261027_observation_receipts` 四表基线。激活时建立或更新当前定义，验证关键列及身份唯一索引后才标记就绪；重复激活不重放历史数据修改、删除或 latest 指针回填。
- PHP 与 Rust 删除 v1 身份摘要算法。上传、手工身份写入及备份写入只支持 `system_uuid_v2`、`baseboard_serial_v2`、`pci_permanent_mac_v2`；不查找 v1 资产，不按编号猜测归属。
- REST、表格导入和备份使用当前字段。二手市场价为 `secondHandMarketValue`，资产写接口拒绝 `residualValue`；备份恢复允许忽略 3.2.3 导出中与当前字段同时出现的冗余旧字段，不能用旧字段回填当前价格；移除旧资产类型转换、扁平身份组及旧身份字段别名。数据库 `residual_value` 是当前内部存储列，无须为改名新增迁移。
- nonce 使用持久对象缓存原子添加或数据库原子声明；限流使用数据库原子计数。删除 transient 与隔离测试专用后备路径，保留 601 秒 nonce 窗口及数据库故障拒绝写入。
- 删除旧导出导入脚本、无用途的国际化空壳及上传中的旧表结构探测。部门配置只从设置读取，不再扫描旧资产回填选项。测试替身适配真实 WordPress 原子接口，不再要求运行时代码适配测试替身。

当前 REST 命名空间中的 `v1`、内部 `v3` 目录、v2 身份、Windows 硬件查询降级和受支持 WordPress/PHP 版本均为当前功能，不因名称或平台差异而删除。

## 备选方案

继续保留所有兼容分支会增加维护和攻击面，与已确认的单用户范围不符。自动删除旧身份或重写历史资产会改变数据归属，因此不采用。保留历史 ADR 和事故记录作为原因证据，并明确标记已替代部分。

## 后果与操作要求

同版本 3.2.3 的导出必须能预览和恢复当前数据。备份中两种停用 v1 身份在预览与实际导入均计入跳过数量并提示，不写入、不参与匹配；未知类型继续拒绝。只有旧价格字段而缺少当前字段的备份仍需转换。其他旧备份和仅含 v1 身份的数据不再保证直接导入。需要接入这类数据时，先做完整离线备份，在独立环境核对并转换为当前结构，验证身份归属、财务值和最新观测指针；运行时不自动修复、合并或删除历史记录。

管理员权限、只读分析、四表职责、归档排除和事务失败回滚继续是验收条件。后续新增兼容层必须有真实需求、明确边界和退出条件。

## 验证

当前 schema 幂等及失败 fixture、资产旧字段/未知身份拒绝、3.2.3 备份冗余字段与 v1 过滤 fixture、上传冲突与回滚、备份恢复、真实数据库认证边界及多站点激活均通过。具体环境、命令和未验证范围见 [本地预览与清理记录](../local-preview-and-compatibility-cleanup-2026-10-27.md)。
