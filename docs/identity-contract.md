# 设备身份契约

## 状态

已接受，2026-10-27 更新。身份算法见 ADR-004；历史兼容层退出决策见 [ADR-017](decisions/ADR-017-remove-historical-compatibility.md)。当前工作区只支持下列三种 v2 身份。

## 身份事实与优先级

服务端只从上传的硬件事实重新计算身份，不接受客户端声明的哈希。一次观测可以产生多个独立身份，按下列顺序排列：

1. `system_uuid_v2`：有效 SMBIOS/系统 UUID，置信度 100。
2. `baseboard_serial_v2`：主板厂商、型号和有效序列号的组合，置信度 100。
3. `pci_permanent_mac_v2`：仅当强信号不可用或未来暂时缺失时使用；由 PCI 物理网卡永久 MAC、主板厂商/型号和 CPU 型号组合，置信度 80。

同一设备可以保存两个强身份和多个 PCI 次级身份。这样某次采集暂时缺少一个信号时，仍可由另一个既有身份匹配。系统 UUID 或永久 PCI MAC 已明确归属某台资产时，重复的主板序列号只能作为辅助事实，不能把上传改派到另一台资产，也不能阻塞该设备的观测写入。两个更强身份分别属于不同资产时，服务端仍返回 `409 identity_evidence_conflict`，不自动合并。

所有身份值都对规范化事实计算 SHA-256，并只保存带版本前缀的摘要。PHP 与 Rust 使用同一无效值矩阵，拒绝全零/全 `F` UUID、已知共享 UUID、OEM 默认串和其他占位值。

## 明确排除

- CPU `ProcessorId`、CPU 序列号：只作为反馈诊断事实，不作为唯一身份；真实样本中两台同型号 Dell 返回了相同 `ProcessorId`。
- USB 网卡：可拔插，不参与自动身份。
- 只有当前 MAC、没有永久 MAC 的网卡：只适合人工核对。
- 硬盘、内存、显卡：属于常换部件，不参与身份。
- TPM：本阶段采集结果不稳定且样本均不可用，不作为上传前置条件。

`notUserRemovable` 也不作为硬条件；真实 PCI 网卡样本没有提供可靠的一致值。身份网卡可来自 Windows `Get-NetAdapter` 或 `root/StandardCimv2:MSFT_NetAdapter`。无论查询来源，PNP 标识必须以 `PCI\\` 开头、`Virtual` 不为真，并且必须包含有效的永久地址。

## 上传决策

1. 服务端计算本次全部 v2 身份，并查找所有已有拥有者；系统 UUID 和永久 PCI MAC 的拥有者优先于主板序列号拥有者。
2. 找到唯一资产后，在事务内锁定并重新读取资产；已归档资产返回 `409 asset_archived`。原子声明本次有效身份，再保存观测、最新指针和事件；任一步骤失败都回滚。
3. 主板序列号已属于另一台资产，但更强身份已经唯一命中时，跳过这条重复辅助身份。其余无法消解的证据或并发声明冲突返回 409，不自动合并。
4. 找不到资产时，以第一个 v2 身份创建新资产并声明本次有效身份；不再计算或查找 v1 身份。
5. 无法计算任何 v2 身份时返回 `422 missing_identity`；不创建资产、观测或事件。

管理员新增身份与备份写入只允许三种 v2 类型。备份中附带的两种旧 v1 身份计入跳过数量并提示，不写入数据库；未知类型仍拒绝。v1 摘要算法、查找与补写路径已删除。缺少 v2 身份的资产需人工核对，不能依赖编号自动关联。

资产编号、上传备注、使用人、主机名和设备型号不参与身份匹配。资产编号可以调整，但已归档资产仍占用原编号；复用编号前必须先给旧资产重编号，再按需要归档，并显式核对身份和观测归属。系统不会根据编号猜测或修正历史归属。

## 采集结构

上传 `_npcink_device.schema_version` 为 5。相对 schema 4 只新增：

- `asset.hardware.processors[]`：Windows 处理器核对事实；
- `asset.hardware.network.identityInterfaces[]`：物理网卡永久地址、PNP 标识和接口元数据。

2026-10-27 在同一 schema 5 中补充内存阵列、独立文件系统卷、OS、机箱、外设、平台原始字段及采集诊断；这些是可选的观测事实，不新增身份类型。完整字段分组见 [完整采集说明](complete-hardware-inventory-2026-10-27.md)。

## 完整采集与可解释降级（2026-10-27 更新）

普通上传、本地检查和硬件 JSON 导出共用完整采集入口，包括主板、处理器身份、永久 PCI 网卡、内存条、物理盘、整机、OS、显示设备、电池及可用外设。快照标记为 `npcink-hardware-inventory-v3`，拒绝复用旧版轻量缓存，上传 observation 仍为 schema 5。可更换部件和新增安全状态只进入观测，不改变身份计算，也不成为上传前置条件。查询超时/失败保留独立诊断并允许其他结果继续上传。

网卡按以下顺序查询，只有取得有效永久 PCI MAC 才停止；查询失败、空结果、仅有当前 MAC 或虚拟网卡，都继续降级：

1. `Get-NetAdapter -Physical -IncludeHidden`
2. `Get-NetAdapter -Physical`
3. `Get-NetAdapter -IncludeHidden`
4. `Get-CimInstance -Namespace root/StandardCimv2 -ClassName MSFT_NetAdapter`

保留每次查询的来源、结果数量、有效永久 PCI MAC 数量和失败类别；查询失败不会伪装成设备不存在该字段。PowerShell 输出统一 UTF-8，支持单对象、数组、空输出和 BOM。多个来源的结果保留为事实，身份层仍按规范化 MAC 去重。

本地快照/硬件反馈新增 `identityDiagnostics`，区分字段 `valid`、`invalid_placeholder`、`missing`，包含查询尝试与最终 `ready` / `needs_review` 决策。它不参与服务端匹配。无身份时，在发起上传之前显示中文分项说明；本地应用日志记录状态，不记录原始身份值。旧版轻量快照、其他版本快照和无法计算身份的快照不再作为有效缓存使用。

当前 MAC、MachineGuid、本地生成的 Agent ID 不升级为硬件身份。它们不能单独证明两次上报属于同一物理设备；没有可信硬件证据时，本版本保留本地反馈并提示管理员核对，不创建服务端“待确认资产”或自动合并。

身份摘要、置信度和当前证据冲突保护保持有效。修复采集能恢复身份计算，但不自动修复此前已经产生的重复资产，也不能仅凭编号把无身份旧资产绑定到新上报。

## 当前上传与重试合同

当前请求只接受HMAC签名v2，绑定HTTP方法、规范化REST路由、Token ID、时间戳、nonce及原始请求体SHA-256。授权范围限定为上传及连接验证；不是逐设备绑定凭据。旧签名无回退，旧客户端需更新而不必重发授权码。精确协议见[异常恢复与上传授权合同](collection-resilience-and-auth-2026-10-27.md)。

接口只接受 `{observation: ...}` 与整数 schema 5。采集时生成 UUIDv4 `_npcink_device.observation_id`，同快照重试保留编号、重新生成鉴权 nonce。服务端按唯一编号及规范化提交内容摘要识别重复；`asset.upload.uploaded_at` 不参与内容摘要，其余事实和备注变化会返回 `observation_id_conflict`。观测编号与请求 nonce 均不参与硬件身份算法。

数据库观测表新增可空 `observation_uuid`、`payload_hash` 及 UUID 唯一索引；无上传凭据的普通观测允许为空。备份保留两字段，按采集编号恢复和去重；同一编号对应不同资产/内容会阻止导入。上传响应只返回资产/观测标识、时间和 mode，不回传完整硬件。原始来源字段与规范化视图各保存一份，raw 只保留采集元数据、上传信息和额外来源信息。
