## 执行顺序与通过条件

每项填写 pass / fail / pending / not applicable、实际耗时和证据位置。故障注入仅作用于指定测试设备或隔离站点；测试后恢复原设置。没有可控故障环境的项目保持 pending，不将未触发重试的一次成功当作恢复测试通过。

| 编号 | 操作 | 通过条件 |
| --- | --- | --- |
| M1 | 原 M4 安装指定哈希的 arm64 包，启动并核对版本 | 原生窗口为 0.4.7；记录安装行为和实际系统安全判定 |
| M2 | 在允许直连的网络导入配置，验证连接并上传一次 | 验证正常、上传成功；后台 receipt 和资产归属正确 |
| M3 | 在指定测试设备启用已批准的手动 HTTP(S) 系统代理，开始新一轮验证和上传 | 新操作读取代理设置，成功或返回可操作的代理分类；记录环境代理是否可能覆盖系统代理；实际代理路径由受控代理侧确认 |
| N1 | 由隔离网关制造一次 503 或连接重置后恢复 | 显示尝试/重试状态，最多 3 次；成功后无残留失败 toast；可切换技术详情，按钮防并发 |
| N2 | 持续返回 503 或制造持续超时 | 最终明确显示类别、尝试次数和下一步建议；网络与退避累计不超过 45 秒预算附近的调度误差，不计采集和本地 I/O |
| N3 | 使用专用已撤销测试授权配置触发 401/403 | 一次尝试即结束，明确授权建议；恢复有效配置后正常成功 |
| N4 | 隔离网关分别返回 302、404、409、413、429 或非 JSON；单独测试不受信任证书 | 对这些错误不自动重试；302 不访问目标；无远端 HTML/堆栈回显；429 给出有效 Retry-After 建议；保持证书校验开启 |
| N5 | 重试等待期间关闭原生窗口；再单独测试明确退出 | 窗口及时消失、退出行为符合预期；记录进程是否残留及时间，发现残留则调查；已送达服务端的请求可能完成，关闭不代表撤销 |
| W1 | Windows 普通用户安装/启动，导入测试配置，采集、验证、上传 | 安装版 0.4.7 可用；身份就绪；后台 receipt 正确；记录 WebView2 和中文路径情况 |
| W2 | 同一 Windows 设备以管理员身份重复采集 | 可用字段和身份归属合理；核对普通用户/管理员差异，不能只记录“程序未报错” |
| W3 | 在指定测试安装上用 0.4.7 覆盖旧正式 0.4.4 | 版本更新、配置及凭据保留、重新验证和上传成功；记录失败恢复与卸载保留行为 |

503 恢复测试按正常插件响应通过隔离网关注入，不构造带认证失败业务码的 503。503 的有效 Retry-After 会限制下一次尝试时间；超过剩余预算应结束。详细分类与退避见[网络策略](upload-network-resilience-2026-11-17.md)。

同一次自动重试应保留同一 observation_id 和请求体，最终只有一条观测。服务器管理员可在受控诊断中比较尝试间 timestamp/nonce/签名是否更新，只输出比较结论和计数，不保存或共享完整认证请求头；这些合同已有 Rust fixture 覆盖。普通客户端 `upload.attempt` 日志不包含 observation_id 或签名，不能据它单独证明签名刷新。手动重新采集产生新编号，不用于证明自动重试幂等。

Windows 可补充执行现有源码 smoke，但需 Node、Rust 和源码；它会在本机写入硬件采集文件，与安装版验收分开记录。以下命令显式不上传、不采集额外系统探针：

```powershell
npm.cmd --prefix .\ele-rs ci
powershell.exe -NoProfile -File .\ele-rs\scripts\windows-smoke-test.ps1 -SkipSubmit -SkipDiagnostics
```

## 结果记录模板

复制以下记录到设备本地，按用例逐条填写后分享脱敏结论：

```text
用例编号 / 结果（默认 pending）：
执行时间 / 操作者 / 设备代号 / OS / 权限：
客户端版本 / 安装包来源 / SHA256：
站点代号 / 插件版本 / 网络与代理模式：
触发条件 / 实际操作：
尝试次数 / HTTP 状态 / 错误类别 / 累计 elapsed_ms：
UI 是否响应 / 最终提示 / 是否有残留 toast：
服务端 receipt 关联核对 / 观测增量 / 身份归属结论：
关闭与进程检查结果（如适用）：
证据位置 / 环境恢复结果 / 未覆盖项：
```

客户端优先摘取 `upload.attempt` 的 category、http_status、attempt、retries、elapsed_ms、retry_delay_ms；站点进一步替换成设备本地约定代号。不要为取证额外启用记录完整请求或响应的代理日志。截图避开配置输入和设备明细。

“排障”页的“生成上传排障包”只在本地生成，但包含采集结果及日志；完整硬件 JSON 还保留序列号、UUID、IP/MAC 等。不要整包提交版本库或公开上传，分享前逐项检查，只提取完成判断所需的脱敏片段。token、secret、完整签名、原始硬件和远端 HTML/堆栈不进入共享验收记录。

## 验收后的交接

完成后将逐项结论回填到[验收证据](agent-0.4.7-acceptance-2026-11-17.md)。任一实机失败项先调查，保留安装包哈希和脱敏证据，不把偶发故障写成已确认的服务器或代理根因。

预览包通过后，按[正式候选流程](github-release.md)准备平台签名、公证和 updater 签名。签名后字节变化，必须重新记录哈希，并对最终包重新验收安装/升级和签名，不能继承预览包的字节验收结论。最终使用[候选验收模板](release-candidate-verification-template.md)汇总；发布既有 draft 仍是单独的人工动作。
