## 结论与范围

依据当前工作区源码、用户两张截图及 device.local 现有最新观测做只读核对。此次仅调查并提出建议，不修改业务代码或资产数据，也不执行 Windows 实机、安装、签名更新或远端 CI。

信息少同时由四类原因造成：普通采集漏项；采集后未装入上传报文；详情页固定选择字段；空值行直接隐藏。后端把收到的 hardware 结构经过通用 JSON 清理后保存，没有针对内存品牌或频率的字段裁剪。

## 处理顺序

1. 修正误导与状态：卷/物理盘命名、CPU 频率语义、主机名/机型区分、内存条数未知、关键字段缺失状态。概览卡片不变，只完善详细信息。
2. 补完整条链路：普通采集与完整采集共用必要硬件函数；上传 OS、机箱、硬件 UUID 和精简诊断；字段清单约束采集、上传、存储、展示，使用实际上传结构回归验证。
3. 补有盘点价值的详细字段：逐条内存、分盘/分卷、主板版本、固件、驱动、IPv6、电池容量。多条部件按部件组织，避免固定每10个属性分页把一根内存切到两页。
4. 后续增强采集：空闲内存槽、可信显存、SMART/SSD寿命、Secure Boot/TPM、多屏刷新率等。按平台和需求增补；静态资产页不默认无限加入实时温度、日志和软件清单。

只维护一套当前规范结构；如需保留已有有效历史事实，可在明确的数据迁移中规范化，不再新增多代上传模式或大批读取别名。密码、授权码、系统产品密钥不属于硬件盘点字段，不应进入详情或默认原始报文展示。
