# Windows 后续实机验收清单

本清单已准备，尚未执行。当前准备验收插件3.2.4 / Agent0.4.5；本地 Rust/JSON 合成测试不替代 Windows PowerShell 5.1、CIM、DXGI 的实际执行。

## 准备与只读采集

记录 Windows 版本、驱动版本、采集器版本和普通/管理员权限。BAT 不再强制提权；总状态 completed 不是完整验收通过，需审阅 coverage 中的跳过和手工步骤。优先使用已有真实样本，不为扩大覆盖而改动硬件。先在 `ele-rs` 目录运行：

```powershell
.\scripts\windows-smoke-test.ps1 -SkipSubmit -SkipDiagnostics
```

该命令构建并测试、本地采集并保存报告，不上传。随后使用已编译的程序分别运行至少5次，以首轮和后续轮次区分系统缓存影响：

```powershell
.\target\debug\npcink-device-agent.exe upload-inspect
```

库存 marker 应为 `npcink-hardware-inventory-v3`。smoke 报告记录采集器耗时、紧凑库存 JSON 字节数及查询状态计数；command wall time 还包含 Cargo/进程启动，不能当作纯采集耗时。库存字节数也不等同最终 HTTP 包大小。原始硬件报告含设备标识，只在本地核对，不放进公开 CI 产物。

## 样本与检查

| 项目 | 样本或核对方法 | 通过条件 |
| --- | --- | --- |
| 内存 | 单条16GB、双条8GB或其他真实组合；对照固件/系统报告 | 条数、各条容量、料号、品牌、速度单位正确；空槽不算已安装条数；系统未报告则留空 |
| 显存 | 已确认8GiB的独显；核对系统工具及厂商规格 | 使用64位 DXGI 值；旧 AdapterRAM 精确原值单列，不当实际容量；共享内存单列 |
| 多卡 | 异型号双卡、相同 PCI 签名双卡（如有） | 异型号按唯一签名对应；相同型号无法唯一匹配时 ambiguous，不按顺序填显存 |
| 显示器 | 单卡单屏、多屏、多卡单屏及相似实例ID | 实例不串配；多卡单屏不套首卡模式；单卡单屏回退有来源；未知刷新率不填60Hz |
| 存储 | 单盘多分区/卷；双盘；如有跨盘卷 | 对照系统 CIM 关联核对设备路径→分区→卷；不重复计算卷容量；无关联与归属冲突有明确状态 |
| 健康 | 支持健康计数器的盘、USB桥接或不支持的盘 | 每条计数器带 StorageUniqueId；单盘失败不丢前后其他盘；失败来源和原因可见 |
| 外设和安全 | USB、打印机、摄像头、TPM、安全启动 | 存储慢查询不阻止安全和外设组先执行；权限不足、不支持、无记录分开解释；TPM=false保留 |
| 身份与网络 | 已有强身份样本、永久PCI MAC降级样本、多个默认路由 | 身份算法不变，无有效身份时不上传；路由、DNS、链路状态来自系统，不靠网卡顺序 |

## 故障与性能

- 分别用普通用户和管理员运行，记录查询级状态，不把无记录解释成无设备。
- 在隔离测试流程模拟单盘读取失败、查询超时、输出截断；已经完整输出的条目仍可用，状态为 partial，缓存60秒后可重试。
- 核心查询预算22秒、网卡降级8秒、可选阶段12秒，均受剩余60秒外部预算限制。可选设备两组最多8秒，存储获得剩余时间；最大并发2，正常比前一阶段多启动一次 PowerShell。另记进程终止及管道清理耗时，不把预算当作整个应用的严格完成时间。
- 记录各查询来源、耗时、返回条数和 partial/failed 原因。比较同一机器、同一权限、同一外设条件下的前后数据；在取得基线前不承诺提速比例或某类设备成功率。
- 大样本本地回归已覆盖512条完整记录加一条截断尾记录；实机需确认大外设列表仍能排空管道并在受控时间退出。超过上传规模限制时须明确拒绝，不静默截掉部件。

## 上传与详情联验

后续仅向专门的 HTTPS 验收站点提交，使用独立测试授权码；不向 `device.local` 写入演示或测试资产。

- 插件与客户端配套使用签名v2。pretty URL、子目录站点、`rest_route` URL都能验证连接；旧签名明确提示更新，原授权码无需更换。
- 重试同一采集编号只保存一条观测；新nonce仍必需。修改方法、路由、Token ID、请求体或加入额外query参数时拒绝请求。
- 上传授权不能读取资产、分析、备份或管理设置。身份冲突、归档资产仍按现有规则拒绝。
- 详情显示全部已采集字段及逐盘失败诊断，0/false保留，空字段默认隐藏，导航仍为八类。入库、导出、恢复后的部件关系逐值一致。

安装、更新签名、回滚和远端CI另按[正式发布流程](github-release.md)执行。私有草稿不能被旧正式客户端的固定latest入口发现；发布前验签及手动安装升级，人工发布已验草稿后在测试安装补官方自动更新 smoke，再推广；不因采集烟测通过就标记这些项目完成。
