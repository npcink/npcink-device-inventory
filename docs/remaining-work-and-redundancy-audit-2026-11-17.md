## 需核对语义或收益后再处理

1. **历史忽略字段仍影响异常清单。** `hardwareAudit.ts` 读取 `metadata.audit.ignoredFields`，可跳过重复 IP、CPU、GPU、内存和磁盘提醒；当前界面没有设置 / 取消该规则的入口，仓库未找到其他写入者。它不是死代码，旧元数据可能改变结果。建议先用受控样本复现，并核对当前资产是否实际携带该元数据，再决定退出旧规则或明确展示来源；不清空真实 metadata，也不新增整套问题处置工作流。
2. **详情过早查询技术资料。** `DetailDrawer.tsx` 打开任意资产即请求身份和最近 20 条完整采集记录，自定义资产也走同样查询；界面却只在电脑高级折叠区使用它们。可按资产类型和展开状态延迟请求；分析采集趋势也可限定在实际展示的视图。保留接口和查看能力，先验证请求数及折叠交互。
3. **详情历史仍存在边界遗漏。** 当前只取最近 20 条采集记录且没有服务器翻页入口，标题使用已加载条数；身份 / 采集请求失败时也缺少与变更记录一致的内联错误和重试状态。应明确“最近 20 条”和总数，按实际查旧记录需求决定补分页或保持有界展示，避免误以为全量历史；无需为此新建独立全局快照页面。
4. **Less 直接依赖候选。** `vite-admin/package.json` 仍声明 `less`，项目源码未找到 Less 文件 / 导入，当前 Ant Design 使用现有样式机制。建议在隔离干净安装中验证移除后再删。`esbuild` 则被两个回归脚本直接使用，不能一起按“Vite 已换构建器”删除。
5. **模板式 Hook Loader 可简化，但优先级低。** loader 的 filter 注册能力未被项目使用，`get_loader()` 也无内部调用；action 注册仍在工作。可以只清除未用部分，不必整体重写插件启动结构。表名定义在父类和 V3 Tables 重复，属于后续维护点，不为减少重复引入本轮 schema 重构。
