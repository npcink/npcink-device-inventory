## 第三轮：导入链路精简与校验

本轮集中检查表格导入，移除重复状态与隐藏格式分支，同时修正可能误改数据的行为：

| 发现 | 处理 |
| --- | --- |
| 选择“仅财务”仍读取并改写 CSV 中的资产类型，分类也可能从未勾选列推断 | 资产类型、分类、名称、状态等基础字段保留原值；未选择的分组不参与预检校验 |
| 只补一个手工硬件字段会替换整个手工硬件对象 | 合并已填写字段，保留其他手工字段、嵌套 raw 与无关元数据 |
| 无效金额被转换成零，非法状态被默认成在用 | 无效值在预览中标错，不进入可执行行；明确的零金额正常接受，空白保留已有值 |
| 购置日期可能被自动修正成另一个日期 | 校验有效的 YYYY-MM-DD 日期，拒绝不存在的日期 |
| CSV 先按换行切割，无法读取自己导出的多行单元格 | 统一按引号和记录边界解析，保留单元格内换行与双引号；拒绝未闭合引号、列数不一致、空或重复表头和缺失编号表头 |
| 导出“采购价”与模板“购置价格”的表头不一致 | 同时识别字段键、模板表头和对应导出表头 |
| 预览保存了可过期的派生数据 | 只保存解析后的源行，依据当前资产索引、部门、策略和分组计算预览；查询中禁止执行，输入改变或解析失败清空旧预览 |
| UI 声明 CSV，解析器仍隐藏接受 JSON | 删除该分支，JSON 继续使用独立备份恢复入口 |
| 预览类型重复存储未使用的购置日期、手工硬件信息 | 删除重复字段及重复构造；信息仍保留在实际提交 input 中 |

Playwright 使用合成资产并延迟资产索引响应，确认加载中预览和执行按钮禁用、加载期间选文件后仍按当前分组与正确已有资产生成预览、切换新增/更新策略和空分组时重算。另验证错误金额和日期说明、修改文本及错误文件清除旧预览，并实际触发两次受路由拦截的提交，检查“仅财务”和“仅手工硬件”的最终请求内容。两次 POST 均由浏览器拦截返回合成成功响应，没有连接真实 WordPress 写接口；无意外 API 路由，最终页面异常为零。其他已有弹窗的 Ant Design `destroyOnClose` 提示和静态 message 上下文提示仍存在，不宣称全站控制台无告警。

## 第四轮：编辑保存定向收尾

按用户确认，最后一轮限定检查自动净值和未展示采购字段的保存行为，确认并修正如下问题：

| 发现 | 处理 |
| --- | --- |
| 三个编辑入口把自动估算写回手工净值字段；清空日期后没有撤销旧估算 | 删除三段自动回写效果。自动方式仅显示估算，保存时从最终采购价、日期和当前折旧设置重新计算；条件被改为不足时清除旧估算，手工零值仍有效 |
| 通用表单将未展示的用途、采购日期、采购人员、店铺、订单等字段写成空值 | 三个入口共用 `shared/assetForm.ts` 的保存转换；缺席字段保留原值，明确提交的空字段才清空，并保留未知扩展信息 |
| 自定义设置从采购元数据中的旧总价、旧标题初始化编辑字段 | 改用资产主记录的采购价和名称，避免保存时覆盖主记录；空分类也保持原值 |
| 通用电脑表单不显示采购日期，其估算却仅监听未注册的日期字段 | 读取已有明确采购日期用于估算，保存仍保留该日期 |
| 价格输入清空后，预览还回退至原采购价 | 清空输入按零值参与估算前置判断，显示无法估算，与提交结果一致 |

历史自动方式已保存的正金额，在采购价、日期和方式均未变化且没有新估算时仍保留；切换为自动、清空或变更估算条件后，无法计算时不会把旧手工值或旧估算继续保存。这里的零仍遵循现有数字存储契约，显示读取在自动方式条件不足时解释为未知。无数据迁移、金额强制填报或服务端接口变更。

先新增保存回归，确认旧实现会清空未展示用途字段，再修正。回归覆盖局部编辑、采购扩展字段、清空日期、价格为零及清空、按最终输入计算、手工零、切换模式、保留未变更的历史值、设置暂不可用和原资产不被修改。

Playwright 在临时浏览器页面挂载实际三个编辑组件，使用合成资产和拦截接口，检查旧采购元数据不覆盖主记录、清空日期/价格、手工零值，以及通用电脑编辑中未展示的日期、数量、采购员、店铺、订单、链接和扩展字段。检查了 4 次被拦截的 PATCH 请求和 2 次表单提交回调；全部使用合成数据，未写入真实资产，最终页面异常为零、无意外 API 路由。保留既有 Ant Design `InputNumber.addonAfter` 开发提示，不扩展为组件库迁移。
